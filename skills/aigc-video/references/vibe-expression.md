# Vibe expression

Vibe is a platform-neutral expression method inside the final video workflow. It decides what the viewer notices and how a supported emotional change becomes visible. It never owns a second output.

## Minimum necessary action

- Preserve: a mature or precision-controlled prompt already works.
- Polish: the facts are complete but the attention path or performance is stiff.
- Compose: the user/project supplies a supported experience or emotional intention but no clear viewing center.

Do not expose these labels unless the user asks about the method.

## Expression core

Define only what the evidence supports:

- one viewing center
- one emotional direction from start to end
- one visual anchor
- the initiating action and resulting state
- one primary performance carrier
- one relation connecting multiple shots, when applicable

Use the source's dominant force:

- narrative: preserve event and causal order
- emotion: strengthen visible rhythm, distance, texture, posture, and sound without adding plot
- memory: use recognition, absence, recurrence, or time slippage already supported by the scene; do not invent a flashback
- subjective perception: keep every image perceivable and related
- functional/commercial: preserve use and product intent; do not force drama

## Hard boundary

Do not add subjects, props, relationships, backstory, symbols, plot turns, emotional reversals, or unassigned reference content. Preserve exact dialogue/audio timing and every lock.

When a user explicitly requests a Vibe version of a low-fit UI, procedure, strict edit, or synchronized-dialogue task, improve only clarity and natural phrasing. Do not add atmosphere to demonstrate Vibe.

For A/B, keep one shared fact-and-lock core in the MotionSpec and attach two variant overlays, then run a delta audit. Without explicit per-variant instructions, vary only unlocked viewer priority, supported performance carrier, atmosphere phrasing, or rhythm. A current-user instruction may scope another named field to A/B; preserve every unscoped user/source/project lock in both variants.
