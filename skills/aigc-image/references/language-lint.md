# Protected image-edit language lint

Use only when an existing image-edit prompt needs clearer language without a new visual decision. Natural language means executable target, change, integration, and preservation—not longer prose.

## Lock ledger

Classify before rewriting:

- `exact`: literal image labels, filenames, visible text, logos, quoted copy, numeric values, ordered references, provider syntax, and parameters the user requires to remain inline
- `semantic`: base image, reference roles, target region, authorized properties, visible endpoint, composition, perspective, contact, light, material, depth, and preservation boundary
- `editable`: tag stacks, repeated boosters, template openings, decorative conclusions, unsupported evaluation words, and awkward connective prose

If a span could be a production control or decoration, keep it locked until the user clarifies.

Before linting, prove that the existing artifact is an image-edit prompt: it names or inherits a base image and an edit target, or the user explicitly calls it an image edit. Otherwise ask whether the text is for image generation, image editing, or video. If two requested medium or style systems imply incompatible render targets, ask for the dominant medium or target instead of blending them by invention.

For a generic AIGC cleanup request with no executable subject, event, or setting, use the same turn to ask both which artifact it is and what visible subject or event must carry the intended meaning. Do not create an author viewpoint or missing visual carrier yourself.

## Intervention

- `preserve`: already clear and executable; return unchanged.
- `micro-fix`: repair local subject-action-space ambiguity, unsupported cause, repetition, or empty adjective.
- `rebuild`: source is mostly tags but still contains enough locked facts to reconstruct the same edit contract. If more than one visual result is plausible, ask before rebuilding.

Do not change provider syntax, aspect ratio, resolution, seed, quality controls, or upload order in language-only mode. If the user asks to change them, return to the owning provider/edit workflow.

## Executability checks

- The sentence names the base image when ambiguous.
- The target object, region, plane, or whole-image property is explicit.
- The edit verb and visible endpoint are explicit.
- Integration states only necessary perspective, contact, occlusion, light, shadow, material, edge, or depth relations.
- Keep states costly locks once; no duplicated negative tail.
- Abstract terms use only source- or prompt-supported visible carriers.
- An off-screen cause is removed when only its visible result is supported, unless direction or cause is an exact lock.
- No new object, light source, effect, prop, camera, composition, color, or action appears.

## Final comparison

1. Compare exact locks character-for-character.
2. Trace every semantic lock to the result.
3. Delete every new noun, verb, number, effect, or relation unsupported by the source prompt or readable image.
4. Return the complete edit prompt, never an isolated sentence patch.

If lock safety and smooth prose conflict, preserve the lock.
